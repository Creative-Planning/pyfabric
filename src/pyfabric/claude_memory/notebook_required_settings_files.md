## The required files

Every `nb_*.Notebook/` artifact directory needs these four files (at minimum):

```text
nb_my_notebook.Notebook/
  .platform                    # display name + logicalId
  notebook-content.py          # the source
  notebook-settings.json       # {"includeResourcesInGit": "on"}
  fs-settings.json             # {"gitExclusions": []}
```

Both settings files use **CRLF** line endings, **no trailing newline**, no BOM. Same convention as `alm.settings.json` / `Sparkcompute.yml`.

## What goes wrong without them

Without `notebook-settings.json`:

- Fabric does **not** include the notebook's `Resources/` subtree in git-sync.
- Any file you add locally to `Resources/builtin/` (wheels, data assets, anything) gets cleaned out by Fabric on the next pull.
- Fabric auto-commits the deletion as a "fabric ui updates" or "Committing N items from workspace …" commit, overwriting your work.
- The flap is one-way and silent — nothing in the git diff explains why the file disappeared.

`fs-settings.json` (`{"gitExclusions": []}`) is the companion. Without it the workspace-side filesystem treats the notebook as having default exclusions, which can also cause sync drift on Resources subtrees.

## Authoring paths that are covered automatically

`NotebookBuilder.save_to_disk()` (≥ v0.1.0rc1) emits `notebook-settings.json` with the correct contents. If your repo creates notebooks via the builder, you get this for free.

## Authoring paths that are **not** covered automatically

Hand-authored notebooks (notebooks copy-pasted from a template, exported from the Fabric portal once and then committed manually, generated by other tooling, etc.) often **lack** these two files. Symptoms:

- A notebook works fine until someone tries to ship a wheel via `Resources/builtin/`.
- The wheel disappears on the next Fabric pull, then a "fabric ui updates" commit lands deleting it.
- Re-pushing the wheel without first adding `notebook-settings.json` reproduces the flap immediately.

When debugging a Resources flap on a hand-authored notebook, the first thing to check is whether `notebook-settings.json` and `fs-settings.json` exist. Copy them byte-for-byte from a known-good notebook in the same repo (or from a fresh `NotebookBuilder.save_to_disk()` output) — the bytes matter.

## Quick fix for an existing notebook

```bash
# From repo root, with nb_OK_notebook as the reference
cp nb_OK_notebook.Notebook/notebook-settings.json \
   nb_BROKEN_notebook.Notebook/
cp nb_OK_notebook.Notebook/fs-settings.json \
   nb_BROKEN_notebook.Notebook/
```

Then commit + push, and re-add the missing Resources file in a follow-up commit.

## Recap

- `notebook-settings.json` + `fs-settings.json` are **required**, not optional, for any git-synced notebook that needs Fabric to honor its Resources folder.
- CRLF, no trailing newline, no BOM.
- `NotebookBuilder.save_to_disk()` covers the build path; hand-authored notebooks need the files added manually.
- A "fabric ui updates" commit deleting files from `Resources/` is the signal that these files are missing.
