- [pyfabric reference](pyfabric.md) — how to use pyfabric (auth, workspaces, lakehouse access) from Python in any repo
- [Descriptions are required by default](descriptions_required.md) — SemanticModel + Report builders raise on save for missing descriptions on visible objects. Always supply meaningful ones; use `is_hidden=True` for housekeeping; do not reach for `strict_descriptions=False`.
- [OneLake direct vs SQL analytics endpoint](onelake_vs_sql_endpoint.md) — prefer OneLake for discovery/scans; FabricSql only for joins or endpoint validation. MirroredDatabase SQL endpoint lags during refresh.
- [Wheel + SqlConn transform pattern](wheel_sqlconn_pattern.md) — canonical pattern for Fabric Spark notebooks: transforms in a pip wheel, DuckDB for local tests, SparkSqlConn in Fabric. Closes the loop with LocalLakehouse.push_table().
- [First refresh needs portal credential binding](first_refresh_cred_binding.md) — Lakehouse.Contents-based SemanticModels always fail the first refresh after git-sync until OAuth creds are bound in the portal. Recognize the error and tell the user; not agent-fixable.
- [Open Mirroring landing-zone protocol](open_mirror_landing_zone.md) — path shape, `_metadata.json` keys, `__rowMarker__` semantics, schema-evolution rules, retention. Read this before writing a producer or hand-rolling landing-zone bytes; pyfabric's `OpenMirrorClient` + `MirroredDatabaseBuilder` are the API.
- [Notebook Resources/builtin wheel pattern](notebook_wheel_resources_pattern.md) — how to ship a project's own helper wheel (fabric_utils, transforms) with a git-synced Fabric Spark notebook so `%pip install "builtin/..."` resolves. **Do not** ship pyfabric or structlog this way — pyfabric is dev-time only. Covers pre-installed runtime packages, notebook-settings.json, case-sensitivity gotcha, LivyClient limitation.
- [Notebook artifact files required for git-sync](notebook_required_settings_files.md) — every git-synced Fabric notebook needs `notebook-settings.json` + `fs-settings.json` or Fabric strips Resources/ on first sync pull. Hand-authored notebooks often miss these files; `NotebookBuilder.save_to_disk()` emits them automatically.
- [Data agent git format + adopt-first tooling](data_agent_git_format.md) — DataAgent files are CRLF + no trailing newline **including `.platform`**; publish_info description = MCP tool description. Author with `fabric-data-agent-sdk`, query/validate via the MCP endpoint; pyfabric owns only git-format validation + normalization.
- [commitToGit can revert .platform description edits](git_commit_description_revert.md) — `updateFromGit` never applies `.platform` `metadata.description` changes to an existing item, so a later `commitToGit mode=All` silently reverts the git-side description. PATCH the item first, then commit. Push direction = `GitClient.commit_to_git` / `sync_workspace(direction=...)`.
- [No production data to cloud AI providers](no_prod_data_to_cloud_ai.md) — default governance rule: production values (and their aggregates) never go to a cloud AI provider; validate with local AI (Foundry Local / Ollama) + synthetic data; per-session override only with a stated signed agreement; projects with their own authorization ship a local memory that supersedes this.
